# Xzdesk 当前产品行为

本文只记录当前软件不可意外破坏的业务行为，不规定开发、测试或验收流程。

## 页面与状态

- 在线客服、客服监控和软件配置是独立模块，页面、菜单和标签状态应保持一致。
- Shopify 渠道、邮箱渠道和客服分配分别显示各自状态。
- 打开软件配置不会自动弹出店铺配置。
- 错误信息应说明失败的操作，不向用户直接显示裸 `404`、`500`、堆栈或敏感凭证。

## Shopify 店铺接入

- 每个店铺独立保存自己的 App Client ID、加密 Client Secret 和加密 Automation Token。
- 新店铺保存后可发布其内部应用版本；发布只允许更新，不自动删除已有扩展。
- 应用版本发布成功前，授权链接和 App Embed 链接保持不可用。
- 已有店铺发布新版本时沿用已保存的凭证，不要求重新输入，也不删除已有插件。
- 授权链接必须使用对应店铺的 Client ID 和 `shop` 参数，不回退到旧的全局 Client ID。
- 旧全局凭证如仍存在，只用于兼容迁移前店铺的卸载 Webhook 校验。
- 授权、App Embed 和 Shopify 后台地址只提供复制，不由 Xzdesk 自动打开。
- 店铺卸载 App 后保留店铺记录，并停用该店铺的 Shopify API 渠道。
- 保存凭证或发布失败时应说明具体失败环节，且不得泄露 Secret 或 Token。

## 邮箱接入与同步

- Outlook 和 Gmail 授权前无需用户手动填写邮箱地址；授权完成后由系统识别邮箱并创建或恢复邮箱渠道。
- 新邮箱默认从授权时刻开始接收；导入最近 7 天最多 100 封未读邮件属于用户主动选择。
- Gmail 使用 `historyId`，Outlook 使用 `deltaLink` 增量同步，已被邮箱客户端标记为已读的新邮件也应正常进入系统。
- 邮件批次成功保存后才能推进同步游标；游标失效时执行有范围限制的近期重新同步。
- 系统至少每天进行一次最近 48 小时的补偿同步，并按邮件服务商的消息 ID 去重。

## 客服分配

- 店铺列表显示已分配客服，并支持直接调整分配。
- 分配修改后列表状态及时更新。
- 移除客服只在店铺配置或明确的管理入口中提供。

## 会话分类与客服备注

- 每个客户会话独立保存三级分类和客服备注。
- 初始分类和备注可由 AI 自动生成；客服人工修改后的内容不得再被 AI 自动覆盖。
- 分类修改立即保存；备注停止输入约 2 秒或离开输入框时保存。
- 切换会话或重新进入后显示服务器最后保存的内容，已结束会话也一样。
- 有店铺权限的客服可以编辑会话记录；全局分类由管理员管理。
- 处理记录支持按店铺、分类、日期和关键词筛选，并导出当前筛选结果。

## 访客快捷服务

- 新建和兼容旧默认配置的访客方案默认提供订单查询，管理员仍可主动关闭。
- 订单查询收集订单号和结账邮箱，并返回最新履约状态和物流信息。
- 桌面聊天窗口约为 `380 × 600`，小屏幕下自适应且不溢出。
- 消息历史独立滚动，输入区和快捷服务始终可操作。
