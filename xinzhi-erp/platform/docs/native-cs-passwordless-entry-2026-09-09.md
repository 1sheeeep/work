## 本次最小变更

- 复用 ERP 已有短时、单次消费、摘要存储及行锁保护的 entry grant，不新增身份库、业务表或迁移。
- 独立 native-entry API 只接受已确认的原客服稳定 ID。签发和兑换均核验原客服身份租约、ERP 会话、账号状态、绑定版本、CHAT 使用资格及客服入口权限；拒绝平台代入身份和本地密码绕行。
- 原客服接收固定 ERP Origin 的 POST 表单，只向固定 HTTPS ERP 地址后台兑换，不跟随重定向。专用服务凭据不与 Shopify Connector 共用，不传 ERP bearer 或密码。
- 原客服按准确源 ID 创建自己的会话，不创建用户、不复制角色、不改密码、不使坐席自动上线，也不撤销其他客服会话。
- 返回页使用 no-store、no-referrer、nonce CSP，凭据不放 URL。只写当前标签页的 sessionStorage；独立标记在退出/过期后保留，禁止回退到浏览器里另一个客服账号。该标签页固定使用当前客服站点，不沿用旧的自定义 API 地址。
- 客服直接登录的原 localStorage 机制保留；ERP 退出不调用客服退出。ERP「到客服修改密码」也经过相同身份交接，避免误入另一个账号。
- 安全模式参考 RFC 9700 的短时单用授权码、固定目标和防登录 CSRF 原则；这是受控第一方交接，不宣称实现完整 OAuth/OIDC 服务。
