| 用户遇到的问题 | 改动 | 实际覆盖 |
| --- | --- | --- |
| 不知道功能归属哪个模块，需要逐层展开菜单 | 顶部“查找功能”，可搜功能及模块名，展示所属路径；支持 Ctrl/Cmd K、Tab、向下键进入结果、Escape 关闭 | 使用当前账号已过滤权限的导航，不建立第二套菜单，不检索业务数据 |
| 商品新增/详情缺少上级列表；部分详情面包屑直接跳过列表 | 主商品子路由映射回主 SKU；详情面包屑补可点击上级 | 主商品、订单、店铺及现有路径前缀型详情 |
| 长页面加载/筛选后自动聚焦把顶部导航滚出视野 | 保留内容焦点但禁止聚焦引起滚动 | AppShell 内所有页面 |
| 高级搜索关闭时卸载输入项，普通搜索丢失已填高级条件 | 保留表单控件，移除提交前关闭；查询被页面接受并变化后关闭，校验失败不关闭 | 主 SKU、库存 SKU、订单高级筛选 |
| 编辑等操作在宽表最右侧，每行都要横向寻找 | 桌面固定操作列，保留悬停/选中背景；小屏仍采用表内横向滚动 | 主 SKU、库存 SKU、订单列表、店铺列表 |
| 只勾选一行时表头仍像完全未选中 | 原生半选状态和 aria-checked=mixed；仍只选择当前页，不改变批量操作范围 | 主 SKU、订单、店铺列表 |
| 店铺页在 390px 视口出现整页横向滚动 | 表格滚动容器定位，约束绝对定位的读屏标题，不删除可访问文本 | 共用表格滚动容器；店铺页实测修复 |
| 普通业务入口同时下载大型平台管理控制台 | 沿用既有路由按需加载，拆出平台登录、凭据和管理页 | 入口 JS 511.70 → 445.84 kB，gzip 150.73 → 136.96 kB；没有改告警阈值 |

本轮公共导航、主要列表交互及入口体积整改已完成，已仅发布 ERP Web。使用精确提交归档，不打包无关未提交文件；后端与 PostgreSQL 容器保持不变，并校验仅 ERP_WEB_IMAGE 一行配置变化。线上只读浏览器核验通过功能查找、仓库/商品列表、操作列固定及筛选草稿保留；没有提交业务写入。
