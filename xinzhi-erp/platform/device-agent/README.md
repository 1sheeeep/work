# KS-01 本地采集 Agent（第一阶段）

这是连接 KS-01 与鑫智 ERP 的本地桥接程序。第一阶段不解析协议、不写 ERP，只完成：

1. 接收 KS-01 的 HTTP、TCP 或 UDP 输出；HTTP 方法和 URL 参数暂不做假设；
2. 保留原始报文（文本、HEX、Base64、来源、时间、远端地址）；
3. 提供本机状态页，方便确认设备是否真的上传；
4. 设备协议未知时，先收集真实样本，避免猜错字段造成错误称重。

## 已覆盖的设备输出方式

公开产品资料显示，HSJ-KS01/KS-01 这类静态扫码称重设备常见输出包括 `Excel`、`HTTP`、`WebSocket`，串口可选；海康读码平台一类上位软件还常见 `TCP`、`UDP`、`HTTP`、`串口` 输出。

当前 Agent 已内置：

| 输出方式 | 当前状态 | 默认配置 |
| --- | --- | --- |
| HTTP | 已支持，适合 `POST/GET` 上传到本机 URL | `http://打包台电脑IP:19091/ks01` |
| TCP Socket | 已支持，适合设备主动连 Agent 端口发送文本/二进制报文 | `打包台电脑IP:19092` |
| UDP | 已支持，适合设备向 Agent 端口发送单包报文 | `打包台电脑IP:19093` |
| WebSocket | 预留，需确认设备是客户端还是服务端，以及握手路径 | 待厂家协议 |
| 串口 RS232/RS485 | 预留，需确认 COM 口、波特率、校验位、停止位、帧格式 | 待厂家协议 |
| Excel/CSV 文件 | 预留，需确认设备是否能导出到固定目录 | 待现场配置 |

## 运行

需要 Go 1.22 或更高版本。复制 `config.example.json` 为 `config.json`，然后执行：

```sh
go run ./cmd/ks01-agent -config ./config.json
```

原始报文会写入 `data/raw-events.ndjson`。程序退出后再次启动，会继续使用同一个文件，不会覆盖历史数据。

验证 Agent 是否启动：

```sh
curl http://127.0.0.1:19091/healthz
curl http://127.0.0.1:19091/status.json
```

模拟一条 HTTP 报文：

```sh
curl -X POST http://127.0.0.1:19091/ks01 \
  -H 'Content-Type: application/json' \
  -d '{"barcode":"TEST-001","weight":1234,"unit":"g"}'
```

模拟一段 TCP 报文：

```sh
printf 'TEST-001,1234,g\r\n' | nc 127.0.0.1 19092
```

模拟一段 UDP 报文：

```sh
printf 'TEST-001,1234,g\r\n' | nc -u 127.0.0.1 19093
```

本机打开 `http://127.0.0.1:19091/status` 查看最近报文。状态页默认只允许本机访问；KS-01 只能访问 `/ks01`，不会看到状态页。

## KS-01 配置

如果 KS-01 使用 HTTP 输出，把上传地址配置为：

```text
http://打包台电脑IP:19091/ks01
```

如果 KS-01 使用 TCP 输出，把目标 IP 配置为打包台电脑的局域网 IP，目标端口配置为 `19092`。

如果 KS-01 使用 UDP 输出，把目标 IP 配置为打包台电脑的局域网 IP，目标端口配置为 `19093`。

打包台电脑需要允许局域网访问对应端口，并建议固定局域网 IP。

由于目前还没有厂家协议文档，HTTP/TCP 报文都按原文落盘。拿到真实样本后，第二阶段再增加解析器和字段校验；解析之前不会把猜测的重量写入 ERP。

## 数据安全

`data` 目录按 0700 创建，原始文件按 0600 创建。第一阶段不连接 ERP，也不保存 ERP 密码、Token 或客户业务数据。
