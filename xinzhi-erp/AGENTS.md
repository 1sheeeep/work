# ERP Project Rules

- Product changes must comply with
  `platform/docs/locked-product-scope-boundaries.md`; existing artifacts and
  general continuation instructions do not override its exclusions or pauses.
- Do not overwrite or remove user-owned data, intentional changes or reference
  materials. An untracked or historical file is not disposable merely because
  of its Git state or age.
- Do not access real production systems, shops, credentials, or the
  customer-service production project without explicit user authorization.
- Do not invent or silently change current user-approved product behavior, data
  contracts or security boundaries.
- Develop one business slice at a time: add only its immediately required
  foundation, keep the backend contract slightly ahead, follow promptly with
  frontend integration, and close the slice before starting another.
- The user owns business and visual acceptance; report evidence without
  declaring acceptance.
