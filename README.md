# 公司内部招聘值守与 AI 简历助手

面向公司内部多个 BOSS 招聘账号的无人值守招聘工具。主链路固定为：真实未读监测 → 超时后回复已审核的企业和岗位事实 → 仅索要一次简历 → 安全提取/去重/OCR → 自动 AI 分析 → HR 查看结果与异常。最终决定始终由 HR 作出。

完整需求、边界与实施顺序见 [`PRODUCT_REQUIREMENTS.md`](PRODUCT_REQUIREMENTS.md)，当前开发状态见 [`DEV_STATE.md`](DEV_STATE.md)。

## 当前架构

```text
招聘管理后台（Java / Vue / PostgreSQL）
             ↓
最小 BOSS 页面桥接器（每账号独立 Chrome Profile）
             ↓
       HR 手动登录的 BOSS 网页
```

真实页面已证实 CDP 附着与 BOSS 页面重定向同时出现，因此生产观测改用项目内置的极小 Manifest V3 桥接器。它不是通用自动化插件，不读取 Cookie、不拦截网络、不使用 debugger。页面写操作默认关闭；只有相应能力通过真实页面验收后，才会执行后端签发的低配额单次任务。系统不保存 BOSS 密码、Cookie、Token 或浏览器 Profile。

当前测试环境必须保持 `APP_BROWSER_MONITOR_ONLY=true`。已通过的当前会话人工测试不等于生产动作批准；后台自动发送执行器、低配额试运行和逐账号生产开启仍属后续安全验收。

## 当前完成情况

- 多招聘账号、真实岗位、挂机值守、简历处理、AI 分析和统一运行日志。
- `LOCAL_CDP_CONNECTOR` 正式账号类型，现有正式账号会由 Flyway V30 自动迁移。
- [`boss-browser-bridge`](boss-browser-bridge/) 支持每账号独立 Profile、一次性连接令牌、安全心跳、稳定双快照和页面内脱敏。[`boss-local-connector`](boss-local-connector/) 暂仅保留离线动作演练和历史诊断工具。
- 桥接器支持 HR 在 BOSS“职位管理”页手动触发当前可见职位同步：只读取具备稳定 DOM 标识的岗位名称、地点、薪资、经验、学历和可见职位描述，在页面内将平台 ID 转换为 SHA-256 摘要后上传。后端按招聘账号、来源摘要和规范化标题去重，只创建或更新待审核草稿；不会自动翻页、点击或修改 BOSS 职位。
- 配对时会登记桥接器类型和版本；后端真实运行接口只接受 `BROWSER_READONLY_BRIDGE`，旧 CDP 设备即使被误启动也无法继续同步真实页面数据。
- 后台默认只监测；桥接器只同步已打开沟通页的未读计数、岗位标题和不可逆摘要。HR 手动打开会话时，它可只读复核最后消息方向与时间，用于生成安全草稿；候选人姓名和消息正文不离开页面脚本，也不执行点击、填写或发送。
- 连接器只把 `/web/chat/index`（以及兼容的历史沟通路径）视为可监测会话页；推荐牛人、岗位列表或其他 `/web/chat/**` 页面均保持暂停。重新配对后，旧设备遗留的未读记录会在新设备首个稳定快照时归档，不计入当前待处理数量。
- BOSS 页面只加载部分会话时，系统不会把本次未出现的历史未读当成已读：这些记录会保留并显示“等待页面再次确认”，同时失去草稿审核资格；桥接器分开显示本次页面未读数和后端持续观察数。
- 选中会话详情必须属于同一轮稳定列表并通过双快照复核，超过 2 分钟或来源设备不一致会被拒绝。打开会话使角标消失不等于 HR 已回复；最后消息仍为候选人来信时系统继续保留待回复状态。
- 图片、表情等非文本最后消息也可只读判断方向和时间，页面内只生成结构摘要，不上传媒体地址。插件会独立显示详情复核结果，不能再用列表数字误判详情已成功。
- 只读未回复监测不依赖 `MESSAGE_SEND`：当前正式账号只需保持已连接，即可设置离开时段和超时阈值并生成待审草稿。首次开启挂机时，尚无策略的账号会自动建立仅生成待审草稿的安全默认策略，不会默认开启自动发送。
- 安全草稿现有结构化资格门禁：岗位标题必须严格、唯一匹配同账号下的启用岗位，企业知识、岗位知识及采集资料必须审核通过。后台会记录匹配岗位、阻断原因和知识版本；不满足条件时完整回退通用文案。HR 可在“今日值守”查看缺项并重新评估，不会触发 BOSS 页面操作。
- “岗位资料”会把真实未读和岗位页面形成的草稿集中到“真实岗位待办”，并在同页内嵌“公司统一回复资料”。HR 可在岗位审核对话框编辑“岗位工作内容”，完成页面核对、回复资料审核和启用。后端原子保存，失败不留下半审核状态；不恢复独立企业页或采集岗位的旧单独启用入口。
- 待审安全草稿会明确显示企业与岗位知识版本，只有完整知识草稿可以批准；企业资料、岗位资料、匹配关系、阻断项或草稿正文变化都会自动撤销旧批准，登记发送动作前还会实时重算并再次校验。
- “今日值守”只在选中的未读因 BOSS 标题与真实岗位不完全一致而无法严格匹配时，显示“关联真实岗位”。只能选择同账号、已启用且回复资料就绪的岗位；跨账号、混合标题或状态变化都会整组拒绝，关联只重算后台草稿。
- 简历分析已接入公司级授权：系统管理员直接在“简历分析”中一次性确认简历处理权限、候选人告知与保留策略。授权后，安全提取的必要文本会在同一内存链路中自动提交 AI 服务；简历原文不会写入本地数据库、文件或审计，AI 不会自动淘汰、录用或对 BOSS 发送消息。BOSS 简历人工恢复只作为漏采/失败异常的兜底入口。
- 已支持 PDF/DOCX 和 PNG/JPG 扫描件 OCR 的无人值守安全处理：文件先经过类型限制、病毒扫描与 SHA-256 去重，文本提取成功后按公司授权自动分析；失败项统一进入 HR 工作台。人工提取、核对和重试入口仅作为异常兜底。
- AI 简历分析的结构化结果、摘要和 HR 对该结果的复核默认保留 90 天；到期后系统自动清除这些内容，保留输入 SHA-256 摘要、时间、模型标识和不可变审计日志。候选人主记录不会被此任务删除。
- 管理后台有 4 个日常入口：今日值守、招聘账号、岗位资料、简历分析；系统管理员另外可访问“HR 用户管理”和“项目运行日志”。企业/集团、候选人 ATS、旧值守设置、独立 AI 服务、运行保障和独立操作日志页面已删，旧 URL 仅兼容重定向到现行页面。
- 前端 E2E 覆盖 4 个日常入口、系统管理员专用的 HR 用户管理与运行日志，以及已删模块旧 URL 重定向；不再运行已删页面的旧业务流程。
- “简历分析”已重构为左侧简历队列与右侧分析看板：BOSS 收到的简历可拖入看板，也可点击选择；拖拽只切换查看对象，不会自动上传、调用 AI 或改变候选人状态。摘要、匹配证据、风险/缺口、追问建议和 HR 复核分区展示，窄屏自动改为单列。
- 今日值守只保留一个挂机开关和挂机期间消息队列；招聘账号主列表以桥接、匿名未读和已同步岗位的真实状态为主，本机接入码和独立 Chrome Profile 配对说明只在连接弹窗出现。AI 服务状态已并入简历分析工作区，不展示环境变量或部署教程。
- 招聘账号页将“最近心跳”和“最后成功同步”分开显示，并展示暂停原因与恢复后重采集证据。桥接重新在线不代表挂机恢复；必须成功入库一轮新的沟通页稳定快照后才显示“恢复已确认”。
- 已清除所有明确标记为 E2E、Mock、UI 的测试招聘数据，保留正式企业、账号和岗位。

## 本地启动

项目根目录已包含 Docker Compose：

```bash
docker compose up -d --build
docker compose ps
```

管理后台：<http://localhost:8088>

初始管理员账号来自本地 `.env` 中的 `APP_BOOTSTRAP_ADMIN_USERNAME` 与 `APP_BOOTSTRAP_ADMIN_PASSWORD`。生产环境必须配置 HTTPS、独立密钥和备份策略。

### HR 账号与登录

HR 使用 <http://localhost:8088/hr-login> 进入专用登录页，或在普通登录页点击“HR 登录入口”。系统管理员登录后，点击顶部右侧用户名和头像，在菜单中选择“创建 HR 登录账号”，设置用户名、显示名、角色、企业范围和初始密码。移动端在侧栏抽屉底部使用同一按钮。

HR 可在登录页勾选“保持登录 7 天”。该功能仅使用服务端可撤销的 HttpOnly Cookie，不保存密码、Cookie 原文或 localStorage token；不勾选时仍使用 8 小时会话。

### 启用兼容 AI 简历分析（当前可使用通义千问/百炼）

默认关闭。完整接入步骤如下：

1. 由公司确认简历可交由外部 AI 服务处理，并确定可发送字段、保留期和 HR 责任人。
2. 使用公司管理的 AI 服务（例如通义千问/阿里云百炼）创建服务端 API Key。不要把 Key 发到聊天、后台页面、日志或 Git。
3. 确认一个已开通、支持 Chat Completions 与 Structured Outputs 的模型名称。
4. 复制 `.env.example` 为项目根目录的 `.env`（已有 `.env` 时只修改对应项），填写：

```bash
APP_OPENAI_ENABLED=true
OPENAI_API_KEY=你的服务端AI服务密钥
OPENAI_MODEL=qwen3.8-flash
OPENAI_BASE_URL=https://ws-ta1pzdoqfltt6o6o.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
OPENAI_TIMEOUT=90s
```

5. 在项目根目录只重建后端容器，让新的服务端环境变量生效：

```bash
docker compose up -d --no-build --force-recreate backend
docker compose ps
```

6. 登录 <http://localhost:8088>，进入“简历分析”确认 AI 分析服务为“可用”；部署人员可按运行日志与后端健康检查完成不含简历数据的连通性验证。
7. 系统管理员在“简历分析”的授权弹窗开启或关闭公司级自动分析；新收到并安全提取的简历会按授权自动分析，HR 在同一页查看结果、异常和必要的 BOSS 简历人工恢复。不再提供独立企业资料或 AI 配置页。

连通性测试失败时，页面会分别提示密钥/权限错误、模型不可用、限额或速率限制、网络请求失败。先按提示修正 `.env` 或 AI 服务项目配置，再重新创建后端容器并测试。

API Key 只存在于后端进程环境，不能写入前端、数据库或 Git。历史环境变量名仍保留为 `OPENAI_*`，其中可存放百炼兼容服务配置。自动调用必须同时满足公司级授权和服务端配置就绪；策略关闭后新简历不得调用。外部服务仍适用其自身的数据处理政策；使用前应按公司隐私制度取得必要授权。

### AI 分析结果保留期

默认 90 天后自动清除 AI 结构化结果、摘要、关联 HR 复核内容和原始 PDF。原始 PDF 清理任务默认每周执行一次；不会删除候选人主记录、输入摘要或审计日志。可在 `.env` 中调整（范围为 1 至 3650 天）：

```bash
APP_RESUME_ANALYSIS_RETENTION_ENABLED=true
APP_RESUME_ANALYSIS_RETENTION_DAYS=90
# 原始 PDF 按保留期清理；清理任务默认每周执行一次。
APP_RESUME_SOURCE_PDF_CLEANUP_INTERVAL=7d
```

清除后的记录仍会在简历工作台显示“已按保留策略清除”，而不会被误报为一次分析失败。

### 启用简历病毒扫描

默认不启动 ClamAV，以避免在没有简历处理需求时占用较多内存。生产启用前请为 Docker 预留至少 4GB 内存，然后在 `.env` 设置 `APP_RESUME_MALWARE_SCAN_ENABLED=true`，并用下面命令启动内部扫描服务；扫描端口只在 Docker 网络内开放，不会映射到电脑或公网：

```bash
COMPOSE_PROFILES=malware-scan docker compose up -d --build
```

启用后，扫描器不可用、超时、检出风险文件或返回异常时，系统会拒绝文件文本提取和 AI 发送，并写入不包含文件内容的审计记录。

### 启用扫描件 OCR 与人工校验

OCR 仅处理 PNG、JPG/JPEG 图片，并且强制要求上述病毒扫描门禁已启用和通过。在 `.env` 同时设置 `APP_RESUME_OCR_ENABLED=true` 后，以以下方式启动两个内部服务：

```bash
COMPOSE_PROFILES=malware-scan,ocr docker compose up -d --build
```

OCR 只在本机 Docker 网络中调用 Tesseract，不会把原始图片发送到外部服务。自动流程固定为“扫描 → OCR 临时提取 → 公司授权检查 → 同一内存链路提交必要文本”；未授权、未配置或失败时转入 HR 工作台，不继续外部分析。

## 多账号只读桥接

真实页面桥接的首次安装和配对见 [`boss-browser-bridge/README.md`](boss-browser-bridge/README.md)。离线动作演练仍见 [`boss-local-connector/README.md`](boss-local-connector/README.md)。

每个账号必须使用不同的：

- Chrome Profile；
- 扩展配对凭据；
- 后台账号 ID；
- 本地连接器凭据。

每个 Profile 单独加载同一份 `boss-browser-bridge` 目录，并使用对应账号的一次性接入码。桥接器本地验证：

```bash
cd boss-browser-bridge
npm run check
npm test
```

通过只代表扩展结构、输入校验和脱敏契约正常；不代表真实 BOSS DOM 已验收，也不会开放生产发送。

桥接器 0.6.0 额外提供人工触发的“已读会话草稿测试”。HR 手动打开允许测试的已读会话并确认输入框为空后，可在 BOSS 页面按 `Option + Shift + D`：扩展只写入固定测试草稿，不点击发送、不模拟 Enter、不领取后台动作租约。测试完成后由 HR 目视确认并手动清空；它不会解锁自动发送能力。

桥接器 0.7.0 新增“填入已审核安全草稿”的人工单次验收链路。HR 在已选中的稳定来信会话中按 `Option + Shift + F`，后端会重新核对岗位/企业知识和审批快照，只签发 60 秒一次性填入凭据。成功后工作台明确显示“已填入未发送”；超时或不确定会冻结为“结果待人工确认”，不会自动重试。该功能仍不会点击发送、模拟 Enter 或开启无人值守发送。

桥接器 0.8.0 增加一个独立的当前会话发送 DOM 测试。它只能在扩展弹窗二次确认后，对 HR 当前已打开的已读会话发送固定测试草稿；不提供快捷键，不切换其他会话，不模拟 Enter，最多点击一次唯一的“发送”按钮。一旦发生点击，无论页面回执成功还是未知，该测试入口都会锁定且不重试。通过此测试不会开启无人值守发送或其他写操作。

桥接器 0.8.1 新增当前会话功能键 DOM 脱敏诊断。它只读识别输入区附近的可见控件结构，供真实页面适配发送、求简历、换电话、换微信和约面试；报告仅留在本机扩展，不包含原始 HTML、消息正文、候选人身份、Cookie 或平台原始 ID，也不会执行任何页面动作。

桥接器会把当前 BOSS 页面归类为沟通页、职位列表、职位详情或其他页面，并在“招聘账号”同步显示。扩展中的“进入对应工作页”只打开本机招聘值守台：沟通页对应今日值守，职位页对应岗位资料；它不会跳转或修改 BOSS 页面，也不会上传完整 URL。

同步岗位时，在对应 Profile 中手动打开 BOSS“职位管理”页；页面保持打开且列表稳定后，扩展会在页面变化时自动只读同步，也可打开扩展点击“同步当前职位页”立即同步。如岗位有分页，由 HR 手动切换页面并逐页同步；系统按账号和标题去重。扩展会同步可见岗位的在招/关闭状态；明确关闭的岗位立即下架，只有无后续分页的完整在招清单才允许用“连续两次缺失”自动下架，避免分页或加载不全误判。重新开放的岗位回到待核对草稿，不会直接参与自动回复。需要完整资料时，由 HR 手动打开某个岗位的编辑详情页，等待表单稳定后再次点击同一按钮。招聘值守台严格按 BOSS 页面显示公司、招聘类型、职位名称、职位描述、职位类型、是否驻外、经验、学历、薪资详情、职位关键词和工作地址；不再提供手工新增职位或混入内部字段。扩展不会点击编辑、保存或发布。回到“岗位资料”点击“刷新同步结果”，展开岗位行即可查看详情；人工核对前不会启用或参与安全回复。

账号掉线、登录失效、验证码、风险提示或页面不确定时，只暂停该账号，不影响其他账号。

### 离线动作演练

连接器包含与 BOSS 页面隔离的 `FIXTURE_ONLY` 动作执行器，用于验证发送消息、索要简历、交换微信和交换电话的前后证据、回执和熔断协议。运行连接器测试即可执行这些演练测试：

```bash
cd boss-local-connector
npm test
npm run drill
npm run drill:faults
npm run drill:isolation
```

`npm run drill` 会依次演练四类受控动作，并只输出动作类型、结果和证据来源。演练不会启动 Chrome、不会读取真实账号页面、不会写入业务数据库、不会创建生产批准，也不会解锁页面写能力。真实页面执行器在逐动作人工验收完成前保持不存在。

`npm run drill:faults` 会注入目标漂移、风险页、状态不变、浏览器输入企图和执行超时五类故障；所有故障都必须被阻断，否则命令以失败状态退出。离线构建清单是开发验收证据，不在 HR 前端展示，也不等同于真实页面验收。

`npm run drill:isolation` 会验证多账号隔离：异常只冻结当前账号、健康探测不能自动解冻、人工恢复必须有三次稳定只读探测，并且恢复后仍保持写能力关闭。

## 安全边界

- HR 手动完成登录、扫码、短信验证和验证码；
- 不调用网页私有接口，不导出 Cookie，不使用无头浏览器；
- 简历向外部 AI 的传输必须由公司级授权控制且可随时关闭；原始 PDF 仅在保留期内保存用于重新分析，不保存 API Key；
- 只在平台当前可见且允许的页面入口中执行操作；
- 发送、求简历、接受简历、交换联系方式均需策略控制、日志和人工接管；
- 页面写动作的成功回执必须包含前后不可逆状态摘要且能证明状态变化；简历接收可关联本轮成功的索要任务，防止跨账号、跨会话或跨周期误绑定；
- 自动化只能降低遗漏，不能保证第三方平台账号绝不受限制。
- 候选人记录只能由受信的真实连接器/简历链路建立；前端不提供手工造候选人、伪造 AI 结论、招聘任务或面试排期入口。
