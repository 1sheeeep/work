# BOSS 只读浏览器桥接

这是每个 BOSS 账号独立 Chrome Profile 中安装的最小 Manifest V3 桥接器。它用来替代会触发真实页面跳转的 CDP 只读附着方案。

## 安全边界

- 只读取已打开沟通页的会话 DOM，以及 HR 手动打开的职位列表或职位详情页；不会自动跳转或翻页。
- 在页面内将会话标识、预览和最后消息转换为 SHA-256 摘要；候选人姓名和消息正文不会上报。
- 沟通页只上传岗位标题；职位列表上传岗位名称、地点、薪资、经验和学历，职位详情页补充招聘类型、职位描述、职位类别、驻外类型、薪数、关键词和详细地址。原始平台 ID 与详情页参数只在页面内生成摘要。
- 不申请 `cookies` / `webRequest` / `debugger` / 下载权限，不读取或传输 BOSS Cookie、Token 和密码。
- 当前版本不包含点击、输入、求简历、交换联系方式或发送消息代码。
- “只读检查回复入口”只连续核对当前会话、可见输入控件和发送按钮的结构摘要，不读取输入内容，不触发页面事件。

## 本地安装（测试阶段）

1. 启动招聘值守台，确认 `http://localhost:8088` 可访问。
2. 在后台“账号与浏览器”为目标 BOSS 账号生成一次性接入码。
3. 在该账号独立 Chrome Profile 中打开 `chrome://extensions`，开启开发者模式。
4. 点击“加载已解压的扩展程序”，选择本目录 `boss-browser-bridge` 。
5. 打开扩展弹窗，粘贴一次性接入码完成配对。
6. 在同一 Profile 中由 HR 手动登录 BOSS，打开沟通页并刷新一次。

## 同步职位资料

1. 在对应招聘账号的独立 Chrome Profile 中手动进入 BOSS“职位管理”。
2. 等待当前页岗位列表加载稳定，打开扩展并点击“同步当前职位页”。
3. 如需完整信息，由 HR 手动打开某个岗位的编辑详情页，等待表单加载完成，再点击同一个“同步当前职位页”。
4. 回到招聘值守台“岗位资料”，点击“刷新同步结果”，展开岗位行查看详情。
5. 逐项核对采集草稿；人工核对并审核前不会启用或参与回复。

如果列表有分页，由 HR 手动切换后逐页同步，后端会按账号、来源摘要和规范化标题去重。页面缺少稳定 ID、字段仍在变化、登录失效或出现风险验证时，采集会立即停止。

多账号部署时，每个 Profile 都单独加载一次此目录，并使用对应账号的一次性接入码。

## 回复页面人工验收准备

1. HR 手动进入 BOSS 沟通页，打开一个允许测试的已读会话。
2. 确认页面没有验证码、风险提示或登录失效。
3. 打开扩展，点击“只读检查回复入口”。扩展会连续检查 3 次，只向后端提交会话和控件的 SHA-256 摘要。
4. 检查通过后，到“值守规则与记录 → 页面能力与受控动作”开启 10 分钟单次人工验收。真实点击、输入和发送仍必须由 HR 手动完成。

## 验证

```bash
cd boss-browser-bridge
npm run check
npm test
```

设计参考了 OpenCLI 的“Profile 隔离 + MV3 后台桥接”思路，但本目录的实现为独立编写，不包含 OpenCLI 或 boss-cli 源码，也不调用 BOSS 私有接口。
